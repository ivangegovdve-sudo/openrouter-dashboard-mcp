# MCP 1.0 Price Sets and Contract Notices Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Release `open-dashboard-mcp` 1.0 with source-backed conditional price sets, refusal-safe comparisons, measured/published speed evidence, install-time selection, and forward deprecation notices, while regenerating the Open Dashboard site from the same contract.

**Architecture:** The 0.9 catalogue becomes the single normalized boundary for every provider: each model exposes `pricePoints`, where every point has exact decimal amount, canonical unit, optional discriminated condition, source URL/date, and provenance. Comparison and normalization operate only on that set and return structured refusals when units or conditions cannot be aligned. A versioned contract envelope is added to package responses and site validation; the package publishes deprecation metadata before future removals.

**Tech Stack:** TypeScript 5.9, Node 20, Zod 4, `tsx --test`, MCP SDK 2, static JavaScript site, Node `node:test`.

**Spec:** User-provided `PROMPT-MCP-1.0` pasted request plus its added section 8 in the conversation.

## Global Constraints

- Exact decimal arithmetic; do not use binary floating point for price values or conversions.
- Every price point has a source URL and date; every normalized figure has an explicit assumption and a source price-point id.
- Conditions are only `latency_window`, `time_band`, `tier`, or `rate_class` until a measured fifth shape exists.
- Three states remain distinct: `published`, `not_published`, and `unknown`; failed acquisition never becomes successful empty pricing.
- Comparisons show all compatible points and their conditions or refuse with a reason; they never silently choose one point.
- Crazyrouter discounts are per-model and derived only where that model's badge exists; DeepSeek peak/off-peak prices are published.
- Speed output contains both `ttft_ms` and `sustained_tps`, with measured/published/unknown state, timestamp, vantage point, prompt hash, and token count.
- Deselecting a provider or tool removes it from responses instead of returning an empty placeholder.
- Never repurpose the old `price` field; 1.0 removes old scalar names and emits a schema version.
- A deprecation notice must contain `removed_in`, `since`, and either `replaced_by` or a plain reason; 1.0 documents that it could not pre-announce its own 0.9-to-1.0 removals.
- Include the 0.9 catalogue in the 1.0 branch even though live `origin/main` does not currently contain merged PR #11.
- Do not add RunPod, Vast.ai, Lambda, or another new provider.
- Before every commit run `git diff --cached --name-only`; keep each commit under 180,000 review characters.
- Open PRs in both repositories and do not merge.
